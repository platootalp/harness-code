# 复杂度评分系统设计文档

> **版本**: 1.0
> **创建日期**: 2026-04-01
> **状态**: 已批准

---

## 1. 概述

### 1.1 设计目标

为 Orchestrator 模块提供复杂度评分能力，根据用户输入自动判定任务复杂度等级（Category），指导后续的编排策略。

### 1.2 核心思路

- **多维指标评分**: 从任务、技术、不确定性三个维度综合评估
- **加权求和**: 任务导向权重 (50% / 30% / 20%)
- **分数映射**: 0-50 → QUICK, 51-80 → DEEP, 81-100 → STRATEGIC

---

## 2. 指标体系

### 2.1 任务维度 (权重 50%)

| 指标 | 0分 | 1分 | 2分 | 3分 |
|------|-----|-----|-----|-----|
| 步骤数量 | 单步 | 2-3步 | 4-5步 | 6步以上 |
| 涉及文件数 | 1个 | 2-3个 | 4-5个 | 6个以上 |
| 涉及模块数 | 1个 | 2个 | 3个 | 4个以上 |

### 2.2 技术维度 (权重 30%)

| 指标 | 0分 | 1分 | 2分 | 3分 |
|------|-----|-----|-----|-----|
| 需搜索代码库 | 不需要 | 简单搜索 | 多处搜索 | 深度探索 |
| 需生成测试 | 不需要 | 简单测试 | 完整测试 | 测试覆盖 |
| 需处理依赖 | 无依赖 | 少量依赖 | 多依赖 | 跨技术栈 |
| 需跨语言/架构 | 否 | 轻微跨 | 中度跨 | 深度跨 |

### 2.3 不确定性维度 (权重 20%)

| 指标 | 0分 | 1分 | 2分 | 3分 |
|------|-----|-----|-----|-----|
| 需求明确度 | 完全明确 | 基本明确 | 部分模糊 | 完全模糊 |
| 实现方案确定性 | 完全确定 | 大概确定 | 需要探索 | 需要创新 |
| 先例/经验 | 有成熟先例 | 类似先例 | 少量参考 | 无参考 |

---

## 3. 分数计算

### 3.1 公式

```
任务维度得分 = (任务指标总和 / 9) × 50
技术维度得分 = (技术指标总和 / 12) × 30
不确定性维度 = (不确定指标总和 / 9) × 20

总分 = 任务维度 + 技术维度 + 不确定性维度
```

### 3.2 维度满分说明

- 任务维度满分: 3指标 × 3分 = 9分
- 技术维度满分: 4指标 × 3分 = 12分
- 不确定性维度满分: 3指标 × 3分 = 9分

## 4. Category 映射

| Category | 分数区间 | 说明 |
|----------|----------|------|
| **QUICK** | 0-50 | 简单任务，单步操作，单文件 |
| **DEEP** | 51-80 | 复杂任务，多步骤，多文件 |
| **STRATEGIC** | 81-100 | 战略任务，跨模块，需要探索创新 |

## 5. 接口设计

### 5.1 Category 枚举

```python
class Category(Enum):
    """任务复杂度类别"""
    QUICK = "quick"       # 快速任务
    DEEP = "deep"         # 深度任务
    STRATEGIC = "strategic"  # 战略任务
```

### 5.2 ComplexityScore 数据类

```python
@dataclass
class ComplexityScore:
    """复杂度评分结果"""
    total_score: float        # 总分 0-100
    category: Category        # 最终类别
    task_score: float         # 任务维度得分
    tech_score: float         # 技术维度得分
    uncertainty_score: float   # 不确定性维度得分
    breakdown: dict[str, int]  # 各指标得分详情
```

### 5.3 ComplexityScorer 类

```python
class ComplexityScorer:
    """复杂度评分器"""

    def score(self, user_input: str) -> ComplexityScore:
        """
        对用户输入进行复杂度评分

        Args:
            user_input: 用户输入文本

        Returns:
            ComplexityScore: 包含各维度得分和最终类别
        """
```

### 5.4 CategoryRouter 类

```python
class CategoryRouter:
    """Category 路由器"""

    def __init__(self, scorer: ComplexityScorer) -> None:
        self._scorer = scorer

    def route(self, user_input: str) -> Category:
        """
        根据用户输入路由到合适的 Category

        Args:
            user_input: 用户输入文本

        Returns:
            Category: 路由结果
        """
        result = self._scorer.score(user_input)
        return result.category
```

## 6. 实现要点

### 6.1 文本分析策略

使用**规则 + 启发式**方法分析用户输入：

1. **步骤数量识别**
   - 枚举词: "首先"、"然后"、"最后"、"第一步"、"第二步"
   - 连接词: "接下来"、"之后"、"接着"

2. **文件/模块数量识别**
   - 文件模式: 代码文件路径、扩展名
   - 模块模式: 包名、目录结构

3. **关键词识别**
   - 搜索类: "搜索"、"查找"、"在哪"、"怎么实现"
   - 测试类: "测试"、"单元测试"、"覆盖率"
   - 依赖类: "依赖"、"安装"、"配置"
   - 多语言: "Python"、"JavaScript"、"API"

### 6.2 评分示例

| 用户输入 | 任务维度 | 技术维度 | 不确定维度 | 总分 | Category |
|----------|----------|----------|------------|------|----------|
| "帮我在这个文件里加一个函数" | 3 (单步、单文件) | 0 | 0 | 16.7 | QUICK |
| "实现用户登录功能，包括注册和验证码" | 7 (多步骤) | 2 | 1 | 45.6 | QUICK |
| "重构订单模块，采用领域驱动设计" | 6 | 6 | 4 | 58.3 | DEEP |
| "设计一个可扩展的微服务架构" | 9 | 9 | 8 | 88.9 | STRATEGIC |
