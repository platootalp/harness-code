## 1. 概述

### 1.1 模块名称

Context（上下文层）

### 1.2 职责

Context 模块是 Mozi AI Coding Agent 的上下文管理层，负责：

- 构建当前任务的上下文信息
- 管理历史消息与会话状态
- 提供向量化检索能力，从 Memory 召回相关记忆
- 整合短期记忆（滑动窗口）和长期记忆（向量化存储）

### 1.3 核心能力

| 能力        | 说明                                                          |
| ----------- | ------------------------------------------------------------- |
| 上下文构建  | 聚合用户输入、历史消息、Memory 数据，生成完整的模型调用上下文 |
| Push 预加载 | 自动预加载高频通用上下文（项目规范、开发偏好等）              |
| 上下文精简  | Compress / Write / Isolate，管理上下文膨胀，对 Agent 透明     |
| 历史管理    | 管理多轮对话历史，支持上下文窗口滑动                          |
| 向量化检索  | 基于 embedding 从长期记忆召回相关内容                         |
| 上下文压缩  | 当上下文超过阈值时，自动压缩或截断                            |
| 会话隔离    | 支持多会话并发，上下文相互隔离                                |

## 2. 核心问题与解决方案

### 2.1 上下文长度限制

**问题描述**：模型有固定上下文窗口，多轮对话后可能超出限制。当会话历史增长时，需要在有限窗口内保留最重要的上下文信息。

**挑战**：如何设计有效的上下文管理策略，在保持关键信息的同时控制 token 消耗。截断策略可能导致重要信息丢失，而过度压缩则影响回复质量。

**解决方案**：实现滑动窗口机制管理对话历史，基于 token 计数器自动控制上下文容量。采用混合压缩策略，保留关键事实和最近对话，摘要中间历史消息，确保重要信息不丢失。

### 2.2 信息检索效率

**问题描述**：从大量历史记忆中快速找到相关内容是一个挑战。检索效率直接影响上下文构建速度和模型响应时间。

**挑战**：向量检索的准确性vs性能权衡。相似度阈值设置不当会导致召回过多噪声或遗漏相关记忆。embedding 模型的选择也影响检索质量。

**解决方案**：使用 embedding 模型将记忆向量化，支持语义相似度检索。实现多层次检索策略，支持按 session_id 和 memory_type 多维度过滤，提高检索精度。

### 2.3 上下文构建复杂性

**问题描述**：上下文需要整合用户输入、历史消息、记忆数据等多个来源。不同来源的数据格式和质量各异，构建过程复杂。

**挑战**：如何协调多个数据源，确保上下文完整且一致。记忆数据与对话历史的融合方式、优先级排序等问题需要仔细设计。

**解决方案**：通过 ContextBuilder 统一协调各数据源，整合用户输入、历史消息、记忆数据。ContextBlock 作为统一的数据结构，简化上下文管理。

### 2.4 上下文压缩质量

**问题描述**：压缩后的上下文需要保留关键信息，不丢失重要上下文。压缩算法需要在信息密度和完整性之间取得平衡。

**挑战**：自动摘要和截断可能丢失关键细节，尤其是隐含的上下文依赖关系。如何评估压缩质量是个难题。

**解决方案**：实现混合压缩策略，保留首尾关键消息，中间消息使用 LLM 生成摘要。对于低价值记忆进行合并压缩，高重要性内容优先保留。

**压缩失真防护**：多轮压缩会导致信息逐层丢失，需采用以下策略：

| 策略           | 说明                                                              |
| -------------- | ----------------------------------------------------------------- |
| **锚点保留**   | 关键决策、用户偏好、当前任务目标等标记为高优先级，跳过压缩        |
| **双向引用**   | 压缩快照保留原始消息 ID 引用，重新加载时可追溯查看原始内容        |
| **递减压缩率** | Snapshot-0→Snapshot-1: 80% 保留，Snapshot-1→Snapshot-2: 60% 保留，越早期越精简但保留骨架 |
| **全量重建**   | 每隔 N 轮用 LLM 重新理解历史生成新摘要，避免累积误差              |
| **质量评估**   | 压缩摘要回灌给 LLM 检查是否与原意一致，不一致则重新压缩或保留原始 |

**压缩保留信息清单**：

| 信息类型       | 优先级 | 处理方式           |
| -------------- | ------ | ------------------ |
| 关键决策点     | P0     | 永不压缩，独立存储 |
| 用户明确偏好   | P0     | 永不压缩，独立存储 |
| 当前任务目标   | P0     | 永不压缩           |
| 已完成操作记录 | P1     | 压缩但保留引用     |
| 中间推理过程   | P2     | 可压缩，保留摘要   |
| 探索尝试记录   | P3     | 可丢弃             |

### 2.5 多会话上下文隔离

**问题描述**：不同会话的上下文需要独立管理，防止数据泄露和干扰。会话隔离是多租户场景下的基本要求。

**挑战**：如何在共享基础设施上实现严格的会话隔离，同时保持良好的性能。隔离机制不能显著增加资源开销。

**解决方案**：每个会话独立上下文对象，通过 session_id 进行隔离。向量存储支持按 session_id 过滤，确保跨会话数据不混淆。

### 2.6 即时上下文与范式转移

**问题描述**：传统上下文构建是**预计算上下文（Pre-computed Context）**模式——在推理前通过检索系统（如 RAG）自动匹配并将结果注入上下文。这种模式下 LLM 是上下文的**被动接收者**，无法决定自己需要什么信息，也无法判断检索结果是否真正有用。

**核心问题**：语义相似度假设的失效。对于复杂 Agent 任务，解决问题所需的信息与问题本身在向量空间中可能相距甚远。例如，修复一个 Bug 可能需要查看造成 Bug 的配置文件，但两者在语义上毫无关联。

**范式转移**：从 **Pre-computed Context** 转向 **Just-in-Time (JIT) Context**——让 LLM/Agent 从上下文的被动接收者转变为主动探索者。

**两个正交维度**：
| 维度 | 被动模式 | 主动模式 |
|------|---------|---------|
| **谁在决策** | 检索系统基于预设规则自动触发 | LLM 自己判断需要什么，决定何时获取 |
| **用什么方法** | 语义搜索 | 精确匹配、文件遍历、API调用等 |

### 2.7 JIT Context 的核心机制

**1. References as Context（引用作为上下文）**

Agent 无需把信息本体塞进上下文，而是依赖轻量级标识符（文件路径、API 端点、网页链接）作为引用。这些引用是极低注意力成本的 token，但提供极高密度的推理线索。例如：

- `tests/test_utils.py` vs `src/utils.py` 隐含完全不同的用途
- 文件夹层级结构、命名惯例、时间戳构成 Agent 对外部世界的"地图"

**2. Progressive Disclosure（渐进式披露）**

Agent 按需逐步获取信息，每一步交互都为下一步决策提供上下文：

- `ls src/` → 查看目录结构，基于命名推断相关模块
- `grep "login" src/auth.py` → 精确匹配特定模式
- `read_file src/auth.py -n 40-60` → 确认目标包含关键逻辑后才加载

这种探索是由**逻辑链条而非语义相似度**驱动，显著降低上下文污染和幻觉风险。

### 2.8 JIT Context 的代价

| 代价           | 描述                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| **延迟问题**   | 多次工具调用的串行交互，Pre-computed 模式可并行检索，JIT 模式通常是决策-执行循环 |
| **工程复杂性** | 需要为 Agent 设计恰当的工具集和启发性指令，不能过于硬编码也不能过于模糊          |
| **过程噪音**   | Agent 的每一次工具调用都会在上下文窗口中留下过程噪音，可能淹没关键信息           |

### 2.9 Compress / Write / Isolate 三种上下文减少策略

这三个策略都是**上下文减少**的手段，区别在于减少的方式和信息损失程度：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        三种上下文减少策略对比                                 │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 策略 1: Compress（压缩）- 有损减少                                          │
│                                                                             │
│   原文 (1K tokens) ──▶ LLM 摘要 ──▶ 摘要 (200 tokens)                     │
│                                                                             │
│   方式：LLM 语义摘要 + 规则剪枝                                               │
│   信息损失：中间过程细节丢失，不可逆                                          │
│   适用场景：需要释放窗口空间时                                              │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 策略 2: Write（写入）- 无损减少                                              │
│                                                                             │
│   完整内容 (2K tokens) ──▶ 写入外部存储 ──▶ 引用路径 (50 tokens)           │
│                                                                             │
│   方式：用引用（文件路径）替换全文                                            │
│   信息损失：无损，可通过引用重新加载                                          │
│   本质：上下文减少，而非压缩                                                  │
│   适用场景：需要保留完整细节但又想减少当前上下文时                           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 策略 3: Isolate（隔离）- 架构层面减少                                        │
│                                                                             │
│   主上下文包含所有子任务详情 (10K tokens)                                    │
│                    │                                                      │
│                    ▼ 派发                                                  │
│   子代理 A 独立上下文 (3K) ──▶ 结论 (200 tokens) ──▶ 回到主上下文          │
│   子代理 B 独立上下文 (4K) ──▶ 结论 (200 tokens) ──▶ 回到主上下文          │
│                                                                             │
│   方式：子代理独立处理，主上下文只接收结论                                    │
│   信息损失：无（每个子代理保留完整细节），但主上下文减少                       │
│   适用场景：复杂多模块任务，需要并行处理时                                   │
└─────────────────────────────────────────────────────────────────────────────┘

总结对比：

| 策略     | 减少方式       | 信息损失 | 可逆性  | 触发条件               |
| -------- | -------------- | -------- | ------- | ---------------------- |
| Compress | LLM 摘要       | 有损     | 不可逆  | 上下文 token >= 阈值   |
| Write    | 引用替换全文   | 无损     | 可重新加载 | 主动触发或定时        |
| Isolate  | 子代理独立处理 | 无损     | 不可重新加载 | 主代理派发子任务     |

关键洞察：
• Write 的本质是用「引用」换「空间」，不是压缩
• Write 实现"上下文无限延伸"——突破窗口限制，细节不丢失
• Isolate 通过架构设计减少主上下文，而非减少信息本身
```

### 2.10 分层加载：压缩快照策略

长会话场景下，历史对话的加载应该是**分层级的**，而非每次从原始消息重压缩。

#### 2.10.1 问题：重复压缩的浪费

```
传统模式（每轮全量加载）：
┌─────────────────────────────────────────────────────────────────────────────┐
│  第 N 轮构建上下文                                                          │
│  ─────────────────────────────────────                                      │
│  加载历史消息 (原始) ──▶ 压缩 ──▶ 摘要 ──▶ 加入上下文                        │
│                                                                             │
│  问题：每次构建都要对相同的历史消息重复压缩，浪费 token 和时间                │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 2.10.2 解决：压缩快照 + 分层加载

```
分层加载模式：
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│  历史消息存储（分层）                                                        │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │  Snapshot-0: 原始消息 (Full)     - 最详细，占用最多 token             │  │
│  │  Snapshot-1: 压缩快照 #1 (50轮摘要)  - 中等精简                       │  │
│  │  Snapshot-2: 压缩快照 #2 (200轮摘要) - 高度精简                       │  │
│  │  Offload: 到外部存储           - 按需加载                             │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  第 N 轮构建上下文：                                                        │
│  ─────────────────────────────────────                                      │
│  最近 10 轮：加载 Snapshot-0 原始消息                                        │
│  最近 11-50 轮：加载 Snapshot-1 压缩快照 #1                                   │
│  更早的：加载 Snapshot-2 压缩快照 #2                                        │
│                                                                             │
│  优势：                                                                     │
│  • 避免重复压缩：压缩结果已持久化，下次直接使用                               │
│  • 按需加载：只加载必要的层级                                                │
│  • 增量演进：压缩快照定期更新，而非每次重建                                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 2.10.3 压缩快照的数据结构

压缩快照的数据结构包含快照标识、覆盖范围、压缩内容和元信息四个部分：

| 字段                | 类型      | 说明                                          |
| ------------------- | --------- | --------------------------------------------- |
| `snapshot_id`       | str       | 快照唯一标识                                  |
| `session_id`        | str       | 所属会话 ID                                   |
| `level`             | int       | 快照层级 (0=原始, 1=第一层压缩, 2=第二层压缩) |
| `start_message_id`  | str       | 起始消息 ID                                   |
| `end_message_id`    | str       | 结束消息 ID                                   |
| `message_count`     | int       | 包含的消息数量                                |
| `summary`           | str       | LLM 生成的摘要                                |
| `key_decisions`     | list[str] | 关键决策点列表                                |
| `unresolved_issues` | list[str] | 未解决的问题列表                              |
| `created_at`        | datetime  | 创建时间                                      |
| `original_tokens`   | int       | 原始 token 数                                 |
| `compressed_tokens` | int       | 压缩后 token 数                               |
| `compression_ratio` | float     | 压缩率                                        |

#### 2.10.4 分层加载的实现逻辑

分层加载器从最新到最旧逐层加载历史消息，直到达到 `max_tokens` 限制：

- **Snapshot-0**：加载最近的原始消息（最近 10 条）
- **Snapshot-1**：加载第一层压缩快照
- **Snapshot-2**：加载第二层压缩快照（更早期）

#### 2.10.5 压缩快照触发时机

```
压缩快照触发规则：

Snapshot-0 (原始消息)：
  → 当消息数 > 50 时，触发 Snapshot-1 压缩
  → 保留最近 10 条原始消息

Snapshot-1 (第一层压缩)：
  → 当 Snapshot-1 快照数 > 3 时，触发 Snapshot-2 压缩
  → 合并多个 Snapshot-1 快照为 Snapshot-2

Snapshot-2 (第二层压缩)：
  → 当 Snapshot-2 快照数 > 3 时，触发 Offload 到外部存储
  → Snapshot-2 快照持久化到文件系统
```

### 2.11 Context 模块整体架构

#### 2.11.1 核心定位：工具提供者 + 窗口管理者

```
┌─────────────────────────────────────────────────────────────────────────────────────┐
│                        Agent 与 Context 模块的关系                                    │
└─────────────────────────────────────────────────────────────────────────────────────┘

       ┌─────────────────────────────────────────────────────────────────────────┐
       │                                Agent                                     │
       │                                                                             │
       │   JIT 是 Agent 的自主行为：                                                │
       │   - Agent 根据任务自主决定调用什么工具                                      │
       │   - Agent 根据推理结果决定是否继续探索                                      │
       │   - 工具调用由 Agent 决策，Context 模块仅执行                              │
       │                                                                             │
       │   ┌───────────────────────────────────────────────────────────────────┐   │
       │   │                        Agent 决策循环                              │   │
       │   │                                                                   │   │
       │   │      ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    │   │
       │   │      │  推理   │───▶│ 决策   │───▶│ 调用工具 │───▶│ 获取结果 │    │   │
       │   │      │         │    │ (探索?) │    │ (grep..) │    │         │    │   │
       │   │      └─────────┘    └─────────┘    └────┬────┘    └────┬────┘    │   │
       │   │                                         │              │         │   │
       │   │                                         └──────────────┘         │   │
       │   │                                                                   │   │
       │   └───────────────────────────────────────────────────────────────────┘   │
       │                                                                             │
       └───────────────────────────────────────────────────────────────────────────┘
                                            │
                                            │ 工具调用 (grep, ls, read_file, vector_search...)
                                            ▼
┌──────────────────────────────────────────────────────────────────────────────────────┐
│                                 Context 模块                                          │
│                                                                                       │
│   角色一：工具提供者 (Tool Provider)                                                  │
│   ┌─────────────────────────────────────────────────────────────────────────────┐   │
│   │                                                                               │   │
│   │   ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │   │

│   │   │  (精确匹配)  │  │ (目录遍历)  │  │ (文件读取)  │  │  (向量检索)  │        │   │

│   │   + ReferenceManager (提供世界地图：目录结构、命名惯例等元信息)                  │   │
│   │                                                                               │   │
│   └─────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                       │
│   角色二：窗口管理者 (Window Manager) - 自动触发，无需 Agent 介入                      │

│   │                                                                               │   │
```

### 2.12 JIT Context 核心机制

JIT Context 的核心是 **Agent 的自主探索行为**，Context 模块提供工具支持和自动化的窗口生命周期管理。

#### 2.11.1 Agent 自主探索模式

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Agent JIT 探索循环                                      │
└─────────────────────────────────────────────────────────────────────────────┘

                         Agent 推理 & 决策
                               │
                               ▼
                    ┌──────────────────────┐
                    │  需要更多信息？        │
                    └──────────┬───────────┘
                               │
              ┌────────────────┴────────────────┐
              │                                 │
              ▼ NO (已有足够上下文)              ▼ YES (需要探索)
        ┌───────────────┐              ┌──────────────────────┐
        │  生成最终回复  │              │ 决定探索策略          │
        └───────────────┘              │ • grep 精确匹配      │
                                       │ • ls 目录遍历        │
                                       │ • read_file 文件读取  │
                                       │ • vector_search 向量检索│
                                       └──────────┬───────────┘
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │  调用 Context 工具    │
                                       │  (grep/ls/read...)   │
                                       └──────────┬───────────┘
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │  获取工具结果         │
                                       │  (匹配行/目录/内容...) │
                                       └──────────┬───────────┘
                                                  │
                                                  └──────────┐
                                                              │
                                          Agent 继续推理 ◀────┘
                                                 ▲
                                                 │
                                          (循环直到任务完成)
```

**关键特点**：

- **Agent 主导**：JIT 探索完全由 Agent 自主决策，Context 模块不预设流程
- **逻辑驱动**：探索基于调用关系、因果链，而非语义相似度
- **按需加载**：只有 Agent 推理确认需要时，才真正加载完整内容

#### 2.11.3 精简机制（模块自动执行，Agent 透明）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        精简机制 (WindowManager 自动触发)                      │
└─────────────────────────────────────────────────────────────────────────────┘

                           上下文窗口状态
                    ┌────────────────────────────┐
                    │  token 数量 < 阈值           │
                    │  (无需精简，正常工作)         │
                    └─────────────┬──────────────┘
                                  │
                                  │ token 数量 >= 阈值
                                  ▼
                    ┌─────────────────────────────────────┐
                    │         WindowManager 自动触发        │
                    │         仅触发 Compress              │
                    └──────────────────┬──────────────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │    Compress      │
                              │      压缩         │
                              │                  │
                              │  LLM 摘要        │
                              │  保留热数据       │
                              │  折叠冷数据       │

                                       │
                                       ▼

                              └──────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│                        三种策略解决不同问题                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Compress（压缩）  → 阈值触发：当 token >= 阈值时自动执行                    │
│                      问题：上下文窗口溢出                                     │
│                      方式：LLM 摘要，有损减少                                 │
│                                                                             │
│  Write（卸载）    → 主动触发：当需要保留高价值上下文细节时                    │

│                      方式：引用替换全文，无损减少                             │
│                                                                             │
│  Isolate（隔离）  → 派发触发：当主代理派发子任务时                            │
│                      问题：子任务过程噪音隔离                                 │
│                      方式：子代理独立处理，主上下文只接收结论                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

精简对 Agent 完全透明，Agent 感知到的上下文始终是"干净"的。
```

```
    │  ├───────────┤  │                │  │ read_file │  │
```

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Isolate 策略：子代理隔离                              │
└─────────────────────────────────────────────────────────────────────────────┘

                         主上下文窗口
                    ┌────────────────────┐
                    │   Task: 复杂多模块  │
                    │      代码分析       │
                    └──────────┬─────────┘
                               │
                 ┌─────────────┼─────────────┐
                 ▼             ▼             ▼
         ┌───────────┐ ┌───────────┐ ┌───────────┐
         │ 子代理 A   │ │ 子代理 B   │ │ 子代理 C   │

         │           │ │           │ │           │

         │ (15K tok) │ │ (20K tok) │ │ (12K tok) │
         └─────┬─────┘ └─────┬─────┘ └─────┬─────┘
               │             │             │
               ▼             ▼             ▼
         ┌───────────┐ ┌───────────┐ ┌───────────┐
         │ 分析结论   │ │ 分析结论   │ │ 分析结论   │
         │ (摘要总结) │ │ (摘要总结) │ │ (摘要总结) │

                    ┌────────────────────┐

                    │  精炼结论 + 引用   │
                    │  (仅 2K tokens)    │
                    │                    │
                    └────────────────────┘
```

**Isolate 的价值**：

- 子代理独立处理复杂任务，过程噪音被隔离
- 主代理只接收精炼后的结论
- 避免大量上下文同时存在于主窗口造成"上下文污染"
- 类似于组织中的层级汇报：基层处理细节，向上级只提交摘要

## 3. 数据模型

### 3.1 核心类型定义

```python
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum
from typing import Any, Literal


class MessageRole(Enum):
    """消息角色"""
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"
    TOOL = "tool"


class SessionStatus(Enum):
    """会话状态"""
    ACTIVE = "active"
    IDLE = "idle"
    ARCHIVED = "archived"
    EXPIRED = "expired"


class MemoryType(Enum):
    """记忆类型"""
    SHORT_TERM = "short_term"    # 短期记忆 - 滑动窗口
    SEMANTIC = "semantic"        # 语义记忆 - 一般知识
    EPISODIC = "episodic"        # 情景记忆 - 过去事件
    PROCEDURAL = "procedural"     # 程序记忆 - 行为模式


@dataclass
class Message:
    """对话消息"""
    id: str
    session_id: str
    role: MessageRole
    content: str
    timestamp: datetime = field(default_factory=datetime.now)
    tool_call_id: str | None = None
    attachment_path: str | None = None  # 大结果存文件
    metadata: dict[str, Any] = field(default_factory=dict)
    streaming_content: str = ""          # 流式输出渐进内容
    is_streaming: bool = False           # 是否正在流式输出


@dataclass
class MemoryBlock:
    """记忆块"""
    id: str
    session_id: str
    content: str
    memory_type: MemoryType
    embedding: list[float] | None = None
    importance: float = 0.5  # 0.0 - 1.0
    status: SessionStatus = SessionStatus.ACTIVE  # ACTIVE/ARCHIVED/DELETED
    created_at: datetime = field(default_factory=datetime.now)
    accessed_at: datetime = field(default_factory=datetime.now)
    metadata: dict[str, Any] = field(default_factory=dict)


@dataclass
class ContextBlock:
    """上下文块"""
    role: MessageRole
    content: str
    metadata: dict[str, Any] = field(default_factory=dict)


@dataclass
class BuiltContext:
    """构建完成的上下文"""
    blocks: list[ContextBlock]
    total_tokens: int
    memory_sources: list[str] = field(default_factory=list)
    truncated: bool = False
    metadata: dict[str, Any] = field(default_factory=dict)


@dataclass
class MetabolismRecord:
    """精简记录 - 追踪上下文的生命周期"""
    session_id: str
    action: Literal["compress", "offload", "isolate"]
    tokens_saved: int
    original_block_ids: list[str]
    timestamp: datetime = field(default_factory=datetime.now)
```

````
| `context/retriever.py` | 检索器实现，基于 embedding 相似度召回 |
| `context/models.py` | 定义 ContextBlock、BuiltContext 等数据模型 |
| `context/offloader.py` | 卸载器，将上下文 Offload 到外部存储（Write 策略） |
| `context/isolator.py` | 隔离器，通过子代理分散过程噪音（Isolate 策略） |

> **注意**：JIT 探索是 Agent 的自主行为，Agent 直接调用 ls、grep、read_file 等工具进行探索，不属于 Context 模块的职责范围。
````

### 6.1 上下文窗口管理

```python
class ContextWindow:
    """上下文窗口管理器"""

    def is_within_limit(self, session: "Session") -> bool:
        """检查是否在限制内"""
        total_tokens = self._estimate_tokens(session)
        return (
            total_tokens <= self._config.max_tokens
            and len(session.messages) <= self._config.max_messages
        )

    def _preserve_last_truncation(self, session: "Session") -> "Session":
        """保留最后 N 条消息的截断策略"""
        max_tokens = self._config.max_tokens
        max_messages = self._config.max_messages
        preserved_messages: list[Message] = []
        accumulated_tokens = 0

        for msg in reversed(session.messages):
            msg_tokens = self._estimate_message_tokens(msg)
            if (
                accumulated_tokens + msg_tokens > max_tokens
                or len(preserved_messages) >= max_messages
            ):
                break
            preserved_messages.insert(0, msg)
            accumulated_tokens += msg_tokens

        return Session(
            id=session.id,
            metadata=session.metadata,
            messages=preserved_messages,
            status=session.status,
            parent_session_id=session.parent_session_id,
        )
```

### 6.2 上下文压缩器实现

````python
class ContextCompactor:
    """上下文压缩器"""

    async def _hybrid_compact(
        self,
        messages: list[Message],
        target_tokens: int,
    ) -> list[Message]:
        """混合压缩：保留首尾消息，中间消息摘要"""
        if len(messages) <= 4:
            return messages

        system_msg = messages[0] if messages[0].role == MessageRole.SYSTEM else None
        preserved_tail = messages[-2:] if len(messages) >= 2 else messages[-1:]
        middle_messages = messages[1:-2] if len(messages) > 2 else []

        if not middle_messages:
            result = []
            if system_msg:
                result.append(system_msg)
            result.extend(preserved_tail)
            return result

        summary = await self._summarize(middle_messages)
        result = []
        if system_msg:
            result.append(system_msg)
        result.append(summary)
        result.extend(preserved_tail)
        return result

    async def _summarize(self, messages: list[Message]) -> Message:
        """使用 LLM 生成摘要"""
        content = self._build_summary_prompt(messages)
        response = await self._model_adapter.invoke(
            messages=[Message(role=MessageRole.USER, content=content)],
        )
        return Message(
            role=MessageRole.SYSTEM,
            content=f"[Summary of earlier conversation]\n{response.content}",
        )


### 6.3 WindowManager 精简实现

```python
class WindowManager:
    """上下文窗口管理器 - 自动触发精简"""

    def __init__(
        self,
        compactor: ContextCompactor,
        offloader: ContextOffloader,
        isolator: ContextIsolator,
        max_tokens: int = 16000,
    ):
        self._compactor = compactor
        self._offloader = offloader
        self._isolator = isolator
        self._max_tokens = max_tokens

    async def ensure_within_limit(
        self,
        context: BuiltContext,
        session_id: str,
    ) -> BuiltContext:
        """
        确保上下文在 token 限制内，自动触发精简策略

        精简策略优先级：Compress -> Write -> Isolate
        """
        if context.total_tokens <= self._max_tokens:
            return context

        original_tokens = context.total_tokens

        # 策略1：Compress - 语义压缩
        compressed = await self._compactor.compact(context.blocks)
        compressed_context = BuiltContext(
            blocks=compressed,
            total_tokens=self._estimate_total_tokens(compressed),
            metadata={**context.metadata, "metabolized": True},
        )

        if compressed_context.total_tokens <= self._max_tokens:
            return compressed_context

        # 策略2：Write - 卸载高优先级块到外部存储
        high_priority = self._select_high_priority_blocks(context.blocks)
        offload_refs = []
        for block in high_priority:
            ref_id = await self._offloader.offload(
                session_id,
                block.content,
                block.metadata.get("importance", 0.5),
            )
            offload_refs.append(ref_id)

        remaining_blocks = [b for b in compressed if b.metadata.get("ref_id") not in offload_refs]
        after_offload = BuiltContext(
            blocks=remaining_blocks,
            total_tokens=self._estimate_total_tokens(remaining_blocks),
            metadata={**context.metadata, "offloaded_refs": offload_refs},
        )

        if after_offload.total_tokens <= self._max_tokens:
            return after_offload

        # 策略3：Isolate - 子代理独立处理（最后手段）
        return await self._isolator.isolate_and_shrink(
            context=after_offload,
            session_id=session_id,
        )
````

```python
@dataclass
class CompressionSnapshot:
    """压缩快照 - 历史消息的压缩结果"""
    snapshot_id: str
    session_id: str
    level: int  # 快照层级 (0=原始, 1=第一层压缩, 2=第二层压缩...)

    end_message_id: str    # 结束消息 ID

    key_decisions: list[str]  # 关键决策点
    unresolved_issues: list[str]  # 未解决的问题

    # 元信息
    created_at: datetime
    original_tokens: int
    compressed_tokens: int
    compression_ratio: float  # 压缩率 = compressed_tokens / original_tokens
```

### 6.5 分层加载器实现

```python
class HierarchicalLoader:
    """分层加载器 - 按层级加载历史消息"""

    def __init__(self, session_store: SessionStore):
        self._session = session_store

    async def load_history(
        self,
        session_id: str,
        max_tokens: int,
    ) -> list[ContextBlock]:
        """
        分层加载历史消息

        策略：从最新到最旧，逐层加载直到达到 max_tokens
        """
        blocks = []
        remaining_tokens = max_tokens

        # Snapshot-0: 加载最近的原始消息（倒序，从新到旧）
        recent = await self._load_recent_messages(session_id, limit=10)
        for msg in reversed(recent):  # 倒序排列： oldest -> newest
            tokens = self._estimate_tokens(msg)
            if tokens > remaining_tokens:
                break
            blocks.append(self._message_to_block(msg))
            remaining_tokens -= tokens

        # Snapshot-1: 加载第一层压缩快照
        if remaining_tokens > 0:
            snapshot_l1 = await self._load_latest_snapshot(session_id, level=1)
            if snapshot_l1 and snapshot_l1.compressed_tokens <= remaining_tokens:
                blocks.append(ContextBlock(
                    role=MessageRole.SYSTEM,
                    content=f"[Earlier Conversation Summary]\n{snapshot_l1.summary}",
                    metadata={"snapshot_id": snapshot_l1.snapshot_id, "level": 1},
                ))
                remaining_tokens -= snapshot_l1.compressed_tokens

        # Snapshot-2: 加载第二层压缩快照（更早期）
        if remaining_tokens > 0:
            snapshot_l2 = await self._load_latest_snapshot(session_id, level=2)
            if snapshot_l2 and snapshot_l2.compressed_tokens <= remaining_tokens:
                blocks.append(ContextBlock(
                    role=MessageRole.SYSTEM,
                    content=f"[Earlier History Summary]\n{snapshot_l2.summary}",
                    metadata={"snapshot_id": snapshot_l2.snapshot_id, "level": 2},
                ))

        return blocks

    async def create_snapshot(
        self,
        session_id: str,
        level: int,
        messages: list[Message],
    ) -> CompressionSnapshot:
        """
        创建压缩快照

        触发条件：当某层级的消息数量达到阈值时，生成该层级的压缩快照
        """
        summary = await self._llm_summarize(messages)
        return CompressionSnapshot(
            snapshot_id=str(uuid.uuid4()),
            session_id=session_id,
            level=level,
            start_message_id=messages[0].id,
            end_message_id=messages[-1].id,
            message_count=len(messages),
            summary=summary,
            key_decisions=[],  # 提取关键决策
            unresolved_issues=[],  # 提取未解决问题
            created_at=datetime.now(),
            original_tokens=self._estimate_total_tokens(messages),
            compressed_tokens=len(summary) // 4,  # 粗略估算
            compression_ratio=0.25,
        )
```
