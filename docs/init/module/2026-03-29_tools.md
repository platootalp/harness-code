## 1. 概述

### 1.1 模块名称

Tools（工具系统）

### 1.2 职责

Tools 模块是 Mozi AI Coding Agent 的核心能力层之一，负责：
- 提供内置工具（Read/Write/Edit/Glob/Grep/Bash/AST-Grep/WebSearch/WebFetch/Skills/LSP）
- 提供任务工具（TaskCreate/TaskGet/TaskUpdate/TaskList）
- 管理外部工具注册与调用
- 维护工具注册表，实现工具发现与路由
- 执行安全检查与权限控制

### 1.3 核心能力

| 能力 | 说明 |
| ---- | ---- |
| 内置工具 | 提供 6 种文件操作工具（Read/Write/Edit/Glob/Grep/Bash） |
| 代码分析工具 | 提供 2 种代码分析工具（AST-Grep/LSP） |
| 外部能力工具 | 提供 3 种外部能力工具（WebSearch/WebFetch/Skills） |
| 任务工具 | 提供 4 种任务操作工具（TaskCreate/TaskGet/TaskUpdate/TaskList），依赖 Task 模块 |
| 工具注册 | 统一的注册/注销/查询接口 |
| 工具执行 | 异步执行工具，支持超时控制 |
| 安全执行 | 沙箱隔离、路径白名单、危险函数检测 |

## 2. 核心问题与解决方案

### 2.1 工具抽象与统一调用

**问题描述**：不同类型工具（内置工具、LSP、外部服务）有不同的调用方式。需要统一的接口让 Agent 能够以相同方式调用所有工具。

**挑战**：内置工具直接本地执行，LSP 工具需要协议通信，Web 检索需要 HTTP 调用。如何设计统一接口同时保持各后端的特殊能力是一大挑战。

**解决方案**：定义 Tool 抽象基类，统一接口定义 execute() 方法。ToolRegistry 维护工具注册表，支持动态注册/注销，通过统一的 execute() 接口调用任意工具。

### 2.2 工具发现与可用性

**问题描述**：Agent 需要知道有哪些工具可用，以及每个工具的用途和参数。工具发现机制直接影响 Agent 的能力范围。

**挑战**：工具列表可能很长，需要有效的文档和描述机制。工具参数的类型和格式验证也是难点。

**解决方案**：通过 ToolRegistry.list_tools() 提供工具元信息查询。每个 Tool 定义 name、description 和 parameters schema，Agent 可据此理解工具用途。

### 2.3 工具执行安全性

**问题描述**：工具执行可能带来安全风险，如文件操作、命令执行等。需要严格的安全检查机制防止恶意操作。

**挑战**：安全检查不能过度影响正常功能。路径白名单、命令限制、沙箱隔离等规则需要仔细设计，兼顾安全性和可用性。

**解决方案**：
- 路径白名单验证：ToolContext 传递安全上下文，使用 WhitelistManager 支持通配符的白名单验证
- 沙箱隔离：SandboxExecutor 采用多层次沙箱隔离策略（进程级、文件系统、网络、资源）
- 危险函数检测：DangerousFunctionDetector 通过 AST 静态分析检测黑名单函数调用
- 权限级别控制：通过 PermissionLevel 枚举（NONE/READ/WRITE/EXECUTE/ADMIN）实现细粒度权限控制

### 2.4 工具执行超时控制

**问题描述**：工具执行时间不可控，可能长时间阻塞影响系统响应。需要有效的超时控制机制。

**挑战**：不同工具有不同的合理执行时间，如何设置合适的超时阈值。超时后如何正确取消和清理资源。

**解决方案**：异步执行工具，通过 asyncio.wait_for 设置超时限制。ToolContext 包含可配置的 timeout 参数，默认 30 秒，超时后取消协程释放资源。

### 2.5 AST-Grep 代码结构搜索

**问题描述**：需要基于代码语法结构进行模式匹配和搜索，而非简单的文本匹配。传统的 Grep 无法理解代码语义。

**挑战**：需要将源代码解析为 AST，并提供表达能力强的模式描述语言。不同语言的 AST 结构差异也增加了复杂性。

**解决方案**：使用 AST-Grep 库实现结构化搜索。支持 `match` 模式表达式、`where` 过滤条件、`rewrite` 替换操作。通过 TreeSitter 解析多语言代码为统一 AST 结构。

### 2.6 LSP 代码分析与补全

**问题描述**：需要深度的代码分析能力，如符号查找、引用跳转、代码补全、诊断信息等。这些能力需要 Language Server Protocol 支持。

**挑战**：LSP 是基于 JSON-RPC 的协议，需要维护服务器生命周期、状态缓存。多个 LSP 服务器的协调也是难点。

**解决方案**：实现 LSP Client 封装，支持服务器启动/停止、请求发送/接收。通过 LSPTool 将各种 LSP 能力封装为统一 Tool 接口。缓存 LSP 响应减少网络开销。

### 2.7 Web 检索能力

**问题描述**：Agent 需要能够检索外部知识，如搜索文档、查询 API、获取最新信息等。

**挑战**：Web 检索涉及网络请求、结果解析、安全验证。需要防止恶意链接和内容注入。

**解决方案**：实现 WebSearchTool，支持主流搜索引擎 API。结果经过安全扫描后返回。使用沙箱环境隔离外部内容访问。

### 2.8 Skills 工具扩展

**问题描述**：用户可能需要自定义工具或能力扩展。需要提供 Skills 机制让 Agent 能够使用用户定义的工具。

**挑战**：Skills 需要安全隔离执行环境，防止恶意代码破坏。参数传递和结果返回也需要标准化。

**解决方案**：实现 SkillsRegistry 管理用户技能定义。每个 Skill 由元数据（名称、描述、参数）和执行函数组成。在沙箱中执行 Skill 代码，返回标准化结果。

### 2.9 WebFetch 内容获取

**问题描述**：Agent 需要获取外部 URL 的内容，如文档、API 响应、网页信息等。

**挑战**：WebFetch 可能遇到认证页面、私密内容、恶意重定向等问题。需要安全验证和内容过滤。

**解决方案**：实现 WebFetchTool，支持 GET/POST 请求。结果经过安全扫描（XSS、注入检测）后返回。使用 httpx 异步客户端，支持超时和重试。

### 2.10 任务工具操作

**问题描述**：Agent 需要创建、查询、更新和列出任务，以支持复杂的多步骤工作流程。任务工具需要与 Task 模块紧耦合。

**挑战**：任务操作的原子性、并发安全、权限控制都需要考虑。任务状态变更需要与其他模块（如 Session）保持同步。

**解决方案**：实现 TaskCreateTool、TaskGetTool、TaskUpdateTool、TaskListTool。通过 TaskModule 提供底层任务管理，工具层做参数验证和结果格式化。事务性操作保证数据一致性。

## 3. 数据模型

### 3.1 核心类型定义

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from enum import IntEnum
from typing import Any


@dataclass
class ToolContext:
    """工具执行上下文"""
    working_directory: str = "."
    session_id: str | None = None
    variables: dict[str, Any] = field(default_factory=dict)
    timeout: int = 30


@dataclass
class ToolResult:
    """工具执行结果"""
    success: bool = False
    output: Any = None
    error: str | None = None
    metadata: dict[str, Any] = field(default_factory=dict)

    def __post_init__(self) -> None:
        if self.success and self.error is not None:
            raise ValueError(
                "Cannot have error message when success is True"
            )


class Tool(ABC):
    """工具抽象基类"""
    name: str
    description: str
    parameters: dict[str, Any] = field(default_factory=dict)

    @abstractmethod
    async def execute(
        self,
        context: ToolContext,
        **kwargs: Any
    ) -> ToolResult:
        raise NotImplementedError


@dataclass
class ASTPattern:
    """AST-Grep 搜索模式"""
    rule: str
    language: str = "python"
    where_constraints: list[str] = field(default_factory=list)


@dataclass
class LSPSymbol:
    """LSP 符号信息"""
    name: str
    kind: int
    location: dict[str, Any]
    container_name: str | None = None


@dataclass
class WebSearchResult:
    """Web 检索结果"""
    title: str
    url: str
    snippet: str
    score: float = 0.0


@dataclass
class Skill:
    """用户自定义技能"""
    name: str
    description: str
    parameters: dict[str, Any]
    code: str
    enabled: bool = True


@dataclass
class WebFetchResult:
    """WebFetch 获取结果"""
    url: str
    status_code: int
    content: str
    headers: dict[str, str]
    error: str | None = None


class PermissionLevel(IntEnum):
    """权限级别枚举"""
    NONE = 0
    READ = 1
    WRITE = 2
    EXECUTE = 3
    ADMIN = 4


class ViolationSeverity(IntEnum):
    """违规严重级别"""
    LOW = 1
    MEDIUM = 2
    HIGH = 3
    CRITICAL = 4


@dataclass
class ToolSecurityContext:
    """工具执行安全上下文"""
    allowed_paths: list[str] = field(default_factory=lambda: ["."])
    permission_level: PermissionLevel = PermissionLevel.READ
    max_execution_time: int = 30
    blocked_functions: list[str] = field(default_factory=list)
    sandbox_enabled: bool = True


@dataclass
class SecurityViolation:
    """安全违规记录"""
    severity: ViolationSeverity
    message: str
    tool_name: str | None = None
    details: dict[str, Any] = field(default_factory=dict)
```

## 5. 接口与交互

### 5.1 ToolRegistry 接口

```python
class ToolRegistry:
    """工具注册表"""

    def __init__(self) -> None:
        self._tools: dict[str, Tool] = {}

    def register(self, tool: Tool) -> None:
        if not isinstance(tool, Tool):
            raise TypeError(
                f"Expected Tool instance, got {type(tool).__name__}"
            )
        if tool.name in self._tools:
            raise ValueError(f"Tool already registered: {tool.name}")
        self._tools[tool.name] = tool

    def unregister(self, name: str) -> bool: ...
    def get(self, name: str) -> Tool | None: ...
    def list_tools(self) -> list[dict[str, Any]]: ...

    async def execute(
        self,
        name: str,
        context: ToolContext,
        **kwargs: Any
    ) -> ToolResult: ...

    def __len__(self) -> int: ...
    def __contains__(self, name: str) -> bool: ...
```

## 6. 核心业务流程

### 6.1 主要流程

```
Actor          Tools              LSP Server         External
  │               │                    │                │
  │─list_tools───►│                    │                │
  │◄─tool_list────│                    │                │
  │               │                    │                │
  │─execute──────►│                    │                │
  │               │─initialize────────►│                │
  │               │◄─server_ready───────│                │
  │               │                    │                │
  │               │─textDocument/*──────────────────────►│
  │               │◄─response────────────────────────────────│
  │               │                    │                │
  │               │─textDocument/didChange────────────────►│
  │               │                    │                │
  │◄─ToolResult────│                    │                │
  │               │                    │                │
```

**步骤说明**：

| 步骤 | 操作 | 说明 |
| ---- | ---- | ---- |
| 1 | list_tools | 获取所有可用工具及其元信息 |
| 2 | execute | 调用指定工具，传递参数 |
| 3 | LSP 初始化 | 与 Language Server 建立连接 |
| 4 | LSP 请求 | 发送代码分析请求 |
| 5 | 结果返回 | 工具执行结果返回给调用者 |

### 6.2 异常流程

| 异常场景 | 处理方式 |
| -------- | -------- |
| 工具不存在 | 返回 ToolNotFoundError |
| 工具执行超时 | 取消执行，返回超时错误 |
| 路径不在白名单 | 返回 PermissionError |
| LSP 服务器无响应 | 重试 3 次后返回连接错误 |
| Web 检索失败 | 返回网络错误，允许重试 |

### 6.3 关键决策点

- **同步 vs 异步**：所有工具执行采用异步模式，避免阻塞主循环
- **LSP 连接管理**：LSP 服务器采用按需启动，空闲超时后自动关闭
- **白名单验证时机**：路径验证在工具执行前进行，而非注册时

## 7. 实现细节

### 7.1 路径白名单验证

```python
def _validate_path(self, context: ToolContext, path: str) -> Path:
    """验证路径是否在允许范围内"""
    resolved = self._resolve_path(context, path)

    # 获取白名单配置
    whitelist = context.variables.get("path_whitelist", ["."])

    # 检查是否在白名单内
    for allowed in whitelist:
        allowed_path = Path(allowed).resolve()
        if resolved.resolve().is_relative_to(allowed_path):
            return resolved

    raise PermissionError(f"Path not in whitelist: {path}")
```

### 7.2 沙箱隔离策略

```python
class SandboxExecutor:
    """沙箱执行器 - 多层次隔离保护"""

    async def execute(
        self,
        command: list[str],
        context: ToolSecurityContext
    ) -> SandboxedResult:
        """在沙箱中执行命令"""
        # 进程级隔离：使用列表参数传递命令
        process = await asyncio.create_subprocess_exec(
            *command,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
            cwd=context.working_directory,
            env=context.environment
        )

        # 超时控制
        try:
            stdout, stderr = await asyncio.wait_for(
                process.communicate(),
                timeout=context.max_execution_time
            )
        except asyncio.TimeoutError:
            process.kill()
            raise ToolExecutionTimeoutError()
```

**沙箱层级**：

| 层级 | 隔离方式 | 保护目标 |
| ---- | -------- | -------- |
| 进程级 | subprocess + 列表参数 | 防止命令注入 |
| 文件系统 | 路径白名单验证 | 防止路径遍历 |
| 网络 | 内部地址禁止访问 | 防止数据外泄 |
| 资源 | 超时 + 内存限制 | 防止资源耗尽 |

### 7.3 危险函数检测

```python
class DangerousFunctionDetector(ast.NodeVisitor):
    """危险函数 AST 检测器"""

    DANGEROUS_FUNCTIONS: dict[str, tuple[str, str]] = {
        "eval": ("HIGH", "eval() allows arbitrary code execution"),
        "exec": ("HIGH", "exec() allows arbitrary code execution"),
        "compile": ("MEDIUM", "compile() can create executable code"),
        "__import__": ("MEDIUM", "__import__() has dynamic import risk"),
        "load": ("HIGH", "pickle.load() has deserialization vulnerability"),
        "loads": ("HIGH", "pickle.loads() has deserialization vulnerability"),
    }

    def visit_Call(self, node: ast.Call) -> None:
        """检测危险函数调用"""
        if isinstance(node.func, ast.Name):
            func_name = node.func.id
            if func_name in self.DANGEROUS_FUNCTIONS:
                severity, message = self.DANGEROUS_FUNCTIONS[func_name]
                self.violations.append(
                    SecurityViolation(
                        severity=ViolationSeverity[severity],
                        message=message,
                        details={"function": func_name}
                    )
                )
        self.generic_visit(node)
```

**黑名单函数**：

| 函数 | 风险等级 | 替代方案 |
| ---- | -------- | -------- |
| eval() | HIGH | ast.literal_eval() |
| exec() | HIGH | 特定功能函数 |
| pickle.loads() | HIGH | json.loads() |
| subprocess.shell=True | HIGH | 列表参数传递 |
| __import__() | MEDIUM | 静态导入 |
| compile() | MEDIUM | ast.parse() |
