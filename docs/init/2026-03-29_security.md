## 1. 概述

### 1.1 模块名称

Security（安全模块）

### 1.2 职责

Security 模块是 Mozi AI Coding Agent 的横切面安全组件，负责：
- 提供统一的安全检查机制
- 管理工具执行白名单
- 实现沙箱隔离保护
- 检测和阻止危险函数调用
- 管理密钥和凭证的安全访问

### 1.3 核心能力

| 能力 | 说明 |
| ---- | ---- |
| 权限模型 | 基于角色的访问控制，细粒度权限配置 |
| 工具白名单 | 支持通配符的路径和命令白名单验证 |
| 沙箱隔离 | 进程级隔离，限制危险操作范围 |
| 危险函数检测 | AST 静态分析检测黑名单函数 |
| 密钥管理 | 环境变量注入，禁止硬编码检测 |
| 安全审计 | 操作日志记录，安全事件追溯 |

## 2. 核心问题与解决方案

### 2.1 恶意代码执行防护

**问题描述**：用户输入可能包含危险命令或代码执行请求。需要防止通过工具调用执行恶意代码。

**挑战**：eval/exec 等函数在合法场景下也可能使用，需要准确检测并避免误报。

**解决方案**：实现 DangerousFunctionDetector 通过 AST 静态分析检测黑名单函数调用。采用基于上下文的权限模型，对代码执行类工具进行额外检查。

### 2.2 路径遍历攻击防护

**问题描述**：文件操作可能访问白名单外的路径，攻击者可能通过路径遍历（如 `../../etc/passwd`）绕过限制。

**挑战**：如何设计既安全又方便的白名单规则，同时保持功能可用性。

**解决方案**：实现 WhitelistManager 支持通配符的白名单验证机制。采用 PathSecurity.validate_and_resolve 进行路径规范化，检查解析后的路径是否在允许范围内。

### 2.3 敏感信息泄露防护

**问题描述**：密钥、密码等敏感信息可能被意外暴露在日志、代码或产物中。

**挑战**：需要在安全性和开发便利性之间取得平衡。

**解决方案**：实现 SecretManager 通过环境变量注入密钥，禁止硬编码。提供 HARDCODED_SECRET_PATTERNS 进行硬编码检测，扫描禁止硬编码密钥。

### 2.4 沙箱隔离与权限控制

**问题描述**：工具执行权限过大，缺乏细粒度控制。某些操作可能影响系统稳定性或安全性。

**挑战**：如何在限制权限的同时保持功能可用。沙箱隔离的实现需要考虑跨平台兼容性。

**解决方案**：实现 SandboxExecutor 采用多层次沙箱隔离策略（进程级、文件系统、网络、资源）。通过权限级别枚举（NONE/READ/WRITE/EXECUTE/ADMIN）实现细粒度权限控制。

## 3. 数据模型

### 3.1 权限体系

```python
class PermissionLevel(IntEnum):
    """权限级别枚举"""
    NONE = 0
    READ = 1
    WRITE = 2
    EXECUTE = 3
    ADMIN = 4


class ViolationSeverity(IntEnum):
    """违规严重级别"""
    LOW = 1
    MEDIUM = 2
    HIGH = 3
    CRITICAL = 4
```

### 3.2 安全上下文

```python
@dataclass
class SecurityContext:
    """安全上下文"""
    user_id: str = "default"
    session_id: str | None = None
    permissions: list[PermissionLevel] = field(default_factory=list)
    working_directory: str = "."
    allowed_tools: list[str] = field(default_factory=list)
    allowed_paths: list[str] = field(default_factory=list)
    resource_limits: dict[str, Any] = field(default_factory=dict)

    def has_permission(self, level: PermissionLevel) -> bool:
        """检查是否具有指定权限级别"""
        if PermissionLevel.ADMIN in self.permissions:
            return True
        return level in self.permissions
```

### 3.3 黑名单函数

| 函数 | 风险等级 | 替代方案 |
| ---- | -------- | -------- |
| eval() | HIGH | ast.literal_eval() |
| exec() | HIGH | 特定功能函数 |
| pickle.loads() | HIGH | json.loads() |
| subprocess.shell=True | HIGH | 列表参数传递 |
| __import__() | MEDIUM | 静态导入 |
| compile() | MEDIUM | ast.parse() |
| open() | LOW | 路径白名单验证后使用 |

## 5. 接口与交互

### 5.1 访问控制流程

```
工具执行请求
    │
    ▼
SecurityContext 构建
    │
    ▼
权限检查（permission check）
    │
    ├──► 无权限 ──► SecurityViolationError
    │
    ▼
白名单验证（whitelist validation）
    │
    ├──► 不在白名单 ──► SecurityViolationError
    │
    ▼
沙箱隔离检查（sandbox check）
    │
    ├──► 违反沙箱规则 ──► SecurityViolationError
    │
    ▼
危险函数检测（dangerous function scan）
    │
    ├──► 检测到危险函数 ──► SecurityViolationError
    │
    ▼
执行工具
```

### 5.2 白名单匹配模式

| 模式 | 示例 | 说明 |
| ---- | ---- | ---- |
| 精确匹配 | `/Users/lijunyi/road/mozi` | 精确路径 |
| 通配符匹配 | `/Users/lijunyi/road/mozi/**` | 匹配目录下所有文件 |
| 正则匹配 | `^/tmp/.*\.tmp$` | 正则表达式匹配 |

### 5.3 安全检查点

| 检查点 | 位置 | 检查内容 |
| ------ | ---- | -------- |
| 入口检查 | Orchestrator | SecurityContext 构建 |
| 工具检查 | ToolRegistry.execute() | 白名单 + 权限 |
| 路径检查 | 文件操作工具 | 路径遍历防护 |
| 命令检查 | BashTool | shell 注入防护 |
| 代码检查 | 执行类工具 | 危险函数检测 |
| 资源检查 | SandboxExecutor | 超时 + 内存限制 |

## 6. 实现细节

### 6.1 沙箱策略

| 层级 | 隔离方式 | 保护目标 |
| ---- | -------- | -------- |
| 进程级 | subprocess + 列表参数 | 防止命令注入 |
| 文件系统 | chroot/jail + 路径白名单 | 防止路径遍历 |
| 网络 | 禁用网络访问 | 防止数据外泄 |
| 资源 | cgroup + ulimit | 防止资源耗尽 |
