# 方案评审报告

> **本模板结构：** 元信息 → 被评摘要 → 发现项 → 开放问题 → 总体结论 → 评审覆盖。发现项中包含「七维索引」子节；总体结论中包含「决策摘要」与「理由」子节；评审覆盖中包含「阅读与假设」与「证据与验证」子节。避免同一信息在文档中重复书写。固定二级标题仅四处，便于检索。

**固定二级标题：** 以下四个标题勿删、勿改名，便于检索与解析：`发现项`、`开放问题`、`总体结论`、`评审覆盖`。

## 被评方案摘要

供读者在未打开被评原文时快速理解方案边界；应用一句话与表格压缩信息，不要整段复述目录。

| 项 | 填写 |
| --- | --- |
| **要解决的核心问题** | 一句话 |
| **非目标 / 明确不做** | 列表；文档未写清则写「见开放问题 Q…」 |
| **交付形态** | 代码 / 插件 / 迁移 / runbook / 混合 |
| **关键外部依赖** | 规格、平台、API、人工步骤；无则写「无」 |
| **安全风险档位** | 低 / 中 / 高 + 一句依据；本栏为评审方自评 |

## 发现项

为每条分配 **F1、F2…**。发现项表格须含 **维度** 列，取值七维之一。下方「七维索引」仅从本表汇总各维对应的 F 编号，不重复展开判断全文。

**推荐表格：**

| ID | 级别 | 位置 | 现象 | 触发条件 | 影响 | 建议 | 维度 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| F1 | 高 | | 一句话概括 | | | 可执行动作 | |

表头说明：**现象** 限一句；**建议** 须为可执行动作。

**级别：** 严重 / 高 / 中 / 低。**维度：** 一致性 / 正确性 / 完整性 / 可执行性 / 安全性 / 可验证性 / 可运维性。

若无阻塞：写 **未发现阻塞性问题**，同段写明 **残余风险** 须具体到事件或条件，并写 **建议补做验证**。

## 总体结论

### 决策摘要

| 项 | 填写 |
| --- | --- |
| **结论** | 四选一：可直接实现 / 修补后可实现 / 需重新设计 / 信息不足 |
| **发现项最高级别** | 严重 / 高 / 中 / 低 / 无阻塞 |
| **是否阻塞实现或发布** | 是或否；若「是」，写明条件 |
| **下一步必须先做的 1～3 件事** | 编号列出，写动作而非「再讨论」 |

### 理由

用 3～8 句说明：点出**最高级别 F 编号**、**评审覆盖**中未验证项对结论信心的影响、**开放问题**中仍待拍板项。勿将决策摘要表格原句再次粘贴到此。

## 评审覆盖

### 阅读与假设

- **已读：** 精确到章节、附件、版本。
- **未读或未验证：** 写明何项、为何未读或未测、对结论的影响。
- **假定：** 若有「假设计划与规格一致」等，逐条列出。

### 证据与验证

与上一节「未读或未验证」对账：缺测试或缺演练即可能构成风险，在「缺口」列标明是否阻塞结论。

| 类别 | 已有 | 缺口 |
| --- | --- | --- |
| 自动化测试 | | 缺什么、是否阻塞 |
| 手工验收 / 演练 | | |
| 监控与日志 | | |
| 回滚或恢复验证 | | |
| 红队 / 滥用面 | | |

某行不适用则填「不适用」。
