# 方案评审清单

> 使用时：复制本清单，随评审过程逐项勾选；可单独保存，或粘贴为《方案评审报告》附录。

## 方案评审：[文档标题或路径]

### 上下文

- [ ] 理解文档要推动的工程变化与预期结果
- [ ] 已明确执行者类型（人 / agent / CI / 运维 / 混合）
- [ ] 已识别影响的资产与约束（数据、权限、用户面、成本、SLA）
- [ ] 已列出依赖的上游规格、代码、平台或流程

### 一致性

- [ ] 目标、非目标、术语与验收标准全文自洽
- [ ] 路径、接口名、版本号、任务顺序前后一致
- [ ] 与上游规格或现有系统无未说明的冲突

### 正确性

- [ ] 架构与数据流能推出承诺结果
- [ ] 状态迁移、权限模型、迁移顺序逻辑闭环
- [ ] 关键假设已写明或已列为开放问题

### 完整性

- [ ] 主路径、失败路径、边界与依赖已覆盖
- [ ] 回滚、清理、发布窗口已覆盖（若适用）
- [ ] 无仅靠「实现时再定」掩盖的关键空白

### 可执行性

- [ ] 步骤具备顺序、输入、输出、责任人或角色
- [ ] 任务粒度可独立验收
- [ ] 隐藏依赖与前置条件已写清

### 安全性

- [ ] 外部输入与自动化写入面已收敛
- [ ] 涉及 agent、hook、写盘、生产数据时存在硬门控或可核验等价物
- [ ] 密钥与权限不出现不可验收表述

### 可验证性

- [ ] 测试/验收/监控与风险级别匹配
- [ ] 覆盖失败、边界、并发或恶意输入（按风险取舍）
- [ ] 回滚或失败恢复可被验证或演练（若适用）

### 可运维性

- [ ] 安装、升级、禁用、卸载或回滚路径可执行（若适用）
- [ ] 可观测性足够定位生产问题
- [ ] 责任交接与半配置恢复有说明（若适用）

### 路径推演

- [ ] 已走通主路径（触发 → 终态）
- [ ] 已走通至少一条失败路径（含检测与恢复）

### 交付物对齐

- [ ] 已按 `references/review-output-template.md` 填写：被评摘要、带 F 编号与维度的发现项、七维索引、总体结论含决策摘要与理由、评审覆盖含阅读与假设及证据与验证
- [ ] 每条发现项含级别、位置、触发条件、影响、可执行建议、维度

### 结论

勾选与总体结论一致的档位；四选一。

- [ ] **可直接实现** — 无严重/高级阻塞
- [ ] **修补后可实现** — 有明确可修项，修补后可通过
- [ ] **需重新设计** — 方向或边界错误，补丁无法救
- [ ] **信息不足** — 缺关键输入，无法负责任结论
